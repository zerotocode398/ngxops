# 账户与个人中心

本模块说明登录、个人资料、密码修改和会话行为。用户、角色与用户组的管理入口属于“用户管理”，见 [rbac.md](rbac.md)。

## 页面与接口

| 方法与路径 | 访问范围 | 说明 |
|---|---|---|
| `GET /login/` | 匿名用户 | 显示登录页；已登录用户会进入首页 |
| `POST /login/` | 匿名用户与 CSRF | 验证账号和密码，并建立登录会话 |
| `POST /logout/` | 已登录用户与 CSRF | 撤销当前会话并返回登录页 |
| `GET /profile/` | 已登录用户 | 查看个人资料 |
| `GET /password/change/` | 已登录用户 | 显示密码修改表单 |
| `POST /password/change/` | 已登录用户与 CSRF | 修改密码并撤销旧会话 |
| `GET /api/session/status` | 页面内部轮询 | 检查会话是否仍有效；已从公开 OpenAPI 文档中排除 |

上述登录、登出和资料页面使用 Jinja2 表单，不是供外部系统集成的 JSON API。页面内写请求需要 CSRF 令牌。`GET /api/session/status` 仅供已登录页面定期检查会话，响应不缓存；会话过期时返回 401 和登录页地址。

## 登录与会话

- 用户名按完整值匹配。未知用户名和密码错误统一提示“用户名或密码错误”；停用账户提示联系管理员。登录记录保存结果和原因，不保存密码。
- 连续输错达到系统设置中的失败次数后，账户会按设定时长锁定。锁定期间不会继续累计错误次数；锁定到期后重新计算，登录成功会清除失败状态。管理员可以在用户管理页面提前解除锁定。
- 登录失败次数和锁定时长由 [settings.md](settings.md) 中的登录设置管理，默认值分别为 5 次和 15 分钟。
- 同一浏览器重复登录会替换旧会话。发现另一浏览器已有会话时，登录页会显示 IP、浏览器信息和确认提示；确认后撤销原会话，取消则保留原会话。原浏览器页面检测到会话已撤销后会提示并跳回登录页。
- `sessionid` 是浏览器会话 Cookie。服务端会话最迟在北京时间登录当天结束时过期；正常关闭浏览器后重新打开需要重新登录，浏览器恢复旧标签页也不能延长服务端有效期。
- 登录默认进入首页；只有经过校验的站内 `next` 地址才会覆盖默认跳转。

## 密码与初始化

密码不会以明文保存。系统使用 PBKDF2-SHA256 生成密码校验值，当前算法参数为 600,000 轮迭代。这是生成校验值时的重复计算轮数，用于提高泄露后的离线猜测成本；它不是用户登录等待的次数，也不需要管理员配置。

修改密码需要提供正确的旧密码，两次新密码必须一致，长度至少为 8 位，且不能过于接近用户名。纯数字和系统内置的常见弱密码也会被拒绝。

首次管理员通过 `ngxops admin create` 创建。命令要求数据库已初始化且尚无用户，并会交互式读取密码。管理员重置密码使用 `ngxops admin reset`。数据库初始化、迁移和管理员创建步骤见 [deployment.md](deployment.md)。
