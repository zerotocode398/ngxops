# 统一异步任务

## 执行协议

业务模块调用 `ngxops.tasks.executor.create_task` 持久化任务并提交可调用函数。可调用函数接收 `TaskContext`，通过以下方法报告执行过程：

- `update_progress(progress, detail)` 更新 0 到 99 的单调进度和当前步骤说明；终态统一写为 100。
- `append_log(message, level, node_id=None)` 追加一条脱敏日志；可选节点 ID 用于按目标筛选多节点执行日志。
- `set_result_tree(value)` 持久化 JSON 结果树。
- `check_cancelled()` 在安全检查点查询取消状态；收到取消时抛出 `TaskCancelled`。
- `register_cancel_callback(callback)` 登记关闭本地 SSH 客户端等资源的回调；取消时执行器会调用已登记回调。

函数返回的非空值会作为最终 JSON 结果树保存。凭证、私钥和会话令牌不得作为普通任务参数、结果或日志传递；已知敏感字段会按键名脱敏，常见敏感赋值与 PEM 私钥块也会在持久化前清理。异常只记录异常类型，不保存异常文本或堆栈。

任务状态为 `pending`、`running`、`success`、`failed`、`cancelled`。任务进度、当前步骤、结果树、日志、批次、目标摘要、触发人及关联资源类型/ID 都持久化。关联资源 ID 不包含密钥或凭证明文。进度更新单调递增；只有 `pending/running` 任务可以继续更新或转成终态。

## 线程和进程边界

- 每个 Web 进程使用容量为 4 的 `ThreadPoolExecutor`，阻塞 SSH 与其他同步 I/O 必须由任务函数在线程池执行，不得直接放进 async 路由。
- 当前执行队列和 Future 取消句柄驻留进程内；SQLite 是状态持久层，不是跨进程队列。部署必须使用单个 Uvicorn worker，不支持多进程重复消费、跨进程取消或任务自动接管。
- 停止进程时不等待长任务，也不杀远端命令。下次启动会将遗留 `pending/running` 任务置为 `failed`，详情记为“服务进程重启，任务已中断”；任务不会自动重跑。
- 取消接口立即将活跃任务置为 `cancelled`，阻止后续进度/结果覆盖终态，并执行已登记的本地资源关闭回调。运行中的本地函数要在检查点协作退出；已经发往远端的命令可能继续运行，取消不会强制终止它。

## JSON API

所有路由都要求登录，应用全局 CSRF 校验适用于取消 POST。

| 方法与路径 | 行为 |
|---|---|
| `GET /api/tasks` | 分页查询可见任务；支持 `status`、`operation_type`、`source_batch`、逗号分隔 `search`、`page`、`page_size`。每个 search 词按批次号/主机名/IP/目标配置名做 OR，词与词之间做 AND。 |
| `GET /api/tasks/{task_id}` | 读取进度、结果树与日志；以 `after_log_id` 和 `log_limit` 增量读取日志，响应的 `next_log_id` 可供下次轮询。通用任务中心日志记录核心操作，可带 `node_id` 供多节点任务筛选；升级/回滚专用详情使用 `log_view=upgrade_full`，安装专用详情使用 `log_view=install_full`，读取同批次逐行远程操作日志。 |
| `POST /api/tasks/{task_id}/cancel` | 协作式取消活跃任务；终态返回 400，取消期间状态竞态返回 409。 |

## 任务中心页面

- `GET /tasks/` 提供统一任务列表，支持按批次号、主机名、IP、配置文件名的多关键词搜索，支持任务类型/状态筛选、每页 10/15/30/50 条和分页；筛选项自动提交，创建时间按 UTC+8 显示。
- `GET /tasks/{task_id}/` 展示触发人、批次、目标、进度、结构化结果树及核心操作日志，不承载专用历史页的全部远程输出。活跃任务每 2 秒轮询状态、结果和增量日志；首屏载入 50 条日志，超过首屏日志量时可继续读取。节点结果摘要单行省略，发布/回滚的长原因可点击展开和收起；所有任务类型使用同一终端文本样式且不显示日志级别，多节点任务可按节点筛选。
- 所有任务详情打开时定位到日志末尾；新增日志会在用户停留末尾时自动跟随，向上滚动查看旧日志后暂停，滚回末尾后恢复跟随。
- 目标节点和目标配置默认各显示前三项，更多项可展开或收起；节点列表 SSH 操作完成提示可直接跳转到对应任务详情。
- 超级管理员和 `releases.read` 可查看全部任务。其他用户只能查看自己创建且操作类型与业务权限匹配的任务；`upgrade.read` 可读取本人升级/安装任务的核心详情，并可在升级或安装专用日志模式中读取对应整批远程日志。普通详情和取消按任务可见范围处理，不可见任务返回 404。
- 任务列表和详情中的发布/回滚批次号仅作摘要；发布历史中的批次号跳转到对应任务详情。其他任务批次可回到任务中心按批次搜索。
- `config_discover` 是 ngxops 配置同步流程实际创建的操作类型，因此任务中心提供该筛选项。旧文档中未启用的 `config_drift_check` 与 `config_glob_preview` 保留兼容但隐藏。

API 的认证、权限、状态码和错误结构见 [api.md](api.md)。

## 业务任务范围

- 节点探测、系统信息采集、Nginx 检测和凭证启用测试都会创建可轮询任务。结果只保存节点状态和摘要，不保存凭证明文或私钥。
- 配置发现和同步任务按节点汇总状态。发现结果只包含远程路径和错误摘要；配置正文不会写入任务参数、结果或日志。完整操作明细可通过增量日志读取，详见 [configs.md](configs.md)。
- 发布与回滚任务按节点和配置绑定保存结果。发布前会备份远程文件；配置校验或 reload 失败时会恢复本批已修改文件。配置正文和 SSH 凭证不进入任务结果，详见 [releases.md](releases.md)。
- Nginx 安装、升级、启停和卸载任务保留各自阶段、节点结果与完整远程日志。任务中心展示核心摘要，相关模块历史详情可查看逐行远程输出；取消为协作式操作，已发送到远端的命令可能继续运行。详见 [upgrade.md](upgrade.md)、[nginx-install.md](nginx-install.md)、[nginx-service.md](nginx-service.md) 和 [nginx-uninstall.md](nginx-uninstall.md)。
